## Steps

First verify, and write down with sources, what nuget.org exposes: unlisting is `dotnet nuget delete <id> <version> --source https://api.nuget.org/v3/index.json` (nuget.org unlists rather than deletes); find out whether deprecation has any public API. If it does not, the command emits a checklist with the exact nuget.org manage-page URLs instead of automating it.
2. `rig estate packages retire --map Iceberg.Net.Core=Lake.Iceberg.Core …` prints the plan; `--apply` runs the parts that have an API, with the API key from the environment, never from a file in the repo.
3. Also verify and document how nuget.org trusted publishing (OIDC) policies are keyed (repository owner/name/workflow) and whether a new package ID can be pushed under an existing policy. H2 depends on the answer.
